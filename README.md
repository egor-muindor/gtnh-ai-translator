# GTNH AI Translator

AI-конвейер для **проверки и улучшения русской локализации** книги квестов модпака
[GregTech: New Horizons](https://www.gtnewhorizons.com/) (BetterQuesting `*.lang`).

Исходный русский перевод — смесь профессионального и машинного перевода: часть строк
отличного качества, а часть выглядит как «после все эти advancements это посмотреть like».
Этот проект находит проблемные строки и переводит их заново, сохраняя при этом хорошие
переводы, всю разметку и порядок файла.

> 🔎 **Просмотр результатов:** [интерактивный viewer на GitHub Pages](https://egor-muindor.github.io/gtnh-ai-translator/)
> — каждый изменённый квест по одному: оригинал (EN) / старый перевод / новый перевод с
> подсветкой различий, рендером цветовых кодов и оценками 👍/👎.

## Принципы перевода

- **Регистр** — неформальный «ты» (как в основной части профессионального перевода).
- **Без избыточной русификации** — названия модов, машин, NEI-предметов, химические формулы
  (`C9H8O4`), аббревиатуры (`BIOS`, `TFFT`), каналы (`#announcements`), команды (`!download`)
  и ссылки остаются как есть. Переводятся описательные игровые термины.
- **Единая терминология** — глоссарий ([`tools/glossary.md`](tools/glossary.md)) собран из
  качественных профессиональных строк и применяется ко всем переводам.
- **Сохранение разметки** — все токены `%n`, `§`-цвета, `[note]/[warn]/[url]/[quest]` и тело
  `[url]` сохраняются 1:1 с источником (проверяется автоматическим QA-гейтом).
- **Сохранение порядка** — исходный `ru_RU.lang` патчится «на месте»; 388 недостающих строк
  вставляются на свои позиции по структуре `template.lang`; комментарии (англ.) не трогаются.

## Как это работает

Конвейер построен на многоагентной оркестрации (Claude Code Workflow) с разделением по
моделям ради качества и стоимости:

```
template.lang + ru_RU.original.lang
        │
        ▼  (детерминированный QA: разметка, garbage-MT детектор)
  [1] Глоссарий      — Haiku ×57   → термбаза из хороших переводов (majority vote)
  [2] Валидация      — Haiku ×205  → проверка КАЖДОЙ строки, список на доработку
  [3] Перевод        — Haiku       → перевод/починка проблемных + 388 недостающих
  [4] Доработка       — Sonnet ×53  → вторая, более сильная модель правит/улучшает (QA-gated)
  [5] Починка разметки — детерм. + Haiku/Sonnet → §-коды и %% к источнику
        │
        ▼
   ru_RU.lang  +  docs/ (viewer)
```

- **Haiku** — массовые операции (дёшево и быстро).
- **Sonnet** — второй проход «валидация + правки» поверх работы Haiku; QA-гейт не даёт
  ухудшить уже хороший перевод (откат к предыдущей версии при провале проверки).
- **Opus** — собрал интерактивный viewer (`docs/`).

Каждый этап проходит через детерминированный QA-гейт ([`tools/qa.py`](tools/qa.py)):
целостность разметки, утечки английского текста (с отличием служебных слов от имён собственных),
непереведённые/пустые строки.

## Структура репозитория

```
├── template.lang            # английский источник (вход)
├── ru_RU.original.lang      # исходный русский перевод (вход, смешанное качество)
├── ru_RU.lang               # ✅ итоговый перевод (результат)
├── FINAL_SUMMARY.md         # сводка по запуску
├── VALIDATION_REPORT.md     # отчёт валидации (что и почему дорабатывалось)
├── tools/                   # CAT-конвейер (Python, без зависимостей)
│   ├── langlib.py           #   парсер/сериализатор .lang (идемпотентный)
│   ├── qa.py                #   QA: разметка + детектор машинного перевода
│   ├── prep.py / batch.py   #   сегментация и нарезка батчей
│   ├── build.py             #   сборка итогового файла (порядок сохраняется)
│   ├── glossary.md/.json    #   термбаза
│   └── ... (валидация, слияние, починка разметки, отчёты)
└── docs/                    # viewer для GitHub Pages (статичный)
    ├── index.html, app.js, styles.css
    └── review_data.json     # 2579 изменённых квестов (EN / старый / новый)
```
